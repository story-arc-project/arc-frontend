# FRT-330: 로그아웃한 사용자의 이탈·체류 기록 유지

사용자가 로그아웃하면 보고 있던 분석 결과의 체류와 작성 중인 경험의 이탈을 해당 사용자의 분석 식별자로 마무리한다. 다음 사용자는 앞 사용자의 체류·진행 정보를 물려받지 않는다.

서버 로그아웃 성공 → `flushExitSignals()` 동기 실행 → `resetUser()` → 인증 상태 정리 → `/login` 하드 이동 순서다. 서버 응답 대기·실패 중에는 기존 세션을 유지한다. 완료한 흐름, 비활성 화면, 숨은 채 한 번도 보이지 않은 체류는 발화하지 않는다.

`useExitSignal` 등록은 언마운트의 지연 콜백이 끝날 때까지 남는다. StrictMode 재개 시 이전 등록과 타이머를 취소해 중복을 막는다. 로그아웃 flush는 거부되거나 예외가 난 세션도 닫고, 다른 콜백과 로그아웃을 계속한다. 따라서 뒤따르는 pagehide·언마운트가 익명이나 다음 사용자로 재발화하지 않는다. 기존 훅 API와 일반 이탈·체류의 판단은 유지한다.

검증: 실제 AuthProvider·분석 클라이언트·useAnalysisViewed·useArchiveEntryAnalytics와 API/PostHog SDK/내비게이션 모형으로 A의 식별자, 5초 체류, 폼 진행, sendBeacon 즉시 전송 옵션, reset 순서와 B 격리를 확인한다. 지연 언마운트·StrictMode·최신 콜백·완료·비활성·숨은 화면·로그아웃 대기/실패·콜백 예외도 회귀 검증한다.

범위는 현재 문서에서 사용자가 명시적으로 누른 로그아웃이다. 다중 탭, 세션 만료, 전역 reset 동작은 변경하지 않는다. 테스트는 SDK 호출 경계까지 확인하며 실제 PostHog 수신이나 실서버 쿠키 삭제를 증명하지 않는다.
