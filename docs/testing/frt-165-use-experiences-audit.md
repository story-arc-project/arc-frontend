# FRT-165 — useExperiences 잔여 회귀 감사

기준: origin/dev `f1d49d2ae714508c4d62e562a3ee21d5d912b880`.
이슈의 “테스트 전무” 설명은 오래되었다. 기존 테스트는 보존한다.
제품 코드·UI·API 계약은 변경하지 않는다. 모든 API는 mock이며 실서버 쓰기는 없다.

| 계약 | 기존 검증 | 이번 추가 |
|---|---|---|
| 복제 삽입·중복 ID 개수 보존 | 있음 | 유지 |
| 오래된 목록 응답 성공/실패 무시·최신 loading/error 소유권 | 있음 | 유지 |
| 복제 hydration vs refetch/delete·동시 복제·StrictMode | 있음 | 유지 |
| 생성/복제 POST 실패 및 성공 후 GET 실패 | 있음 | CRUD 실패 상태·재조회 복구까지 확장 |
| 생성/수정/중요도(5/null)/삭제 정확한 요청 인자 | 없음 | 각 API 1회·인자 단언 |
| 쓰기 완료 전 GET 금지, GET 완료까지 mutation 대기 | 없음 | deferred 쓰기/조회로 순서 검증 |
| CRUD 성공 후 서버 목록·서버 count 동시 교체 | 없음 | count가 페이지 길이와 다른 응답 포함 |
| CRUD 쓰기 실패는 reject, GET 금지·기존 상태 보존 | 생성 reject만 있음 | 나머지 쓰기 및 상태 단언 |
| CRUD 성공 후 조회 실패는 쓰기 성공 유지 | 생성 반환값만 있음 | error/loading/목록/count·재조회 복구·쓰기 재시도 없음 |
| 쓰기 대기 중 unmount 후 후속 GET 금지 | 생성/복제 있음 | 수정/중요도/삭제 확장 |
| 최초 조회의 비 Error 실패 정규화·재시도 | 없음 | 추가 |

중복 요청: 훅이 쓰기를 deduplicate하는 계약은 없다. 기존 동시 복제 테스트는
서로 다른 복제 결과 보존을 검증한다. 이번 테스트는 호출당 API 1회와 조회 실패 후
쓰기 재시도 없음만 단언하며, 새 중복 방지 제품 정책을 도입하지 않는다.

범위 밖: 실 백엔드 통합, 서버 권한/삭제 의미, UI 중복 클릭 차단.
