# BAC-38: 공개 패키지 조회 API 제안

상태: 프론트 구현 기준 제안, 백엔드 합의·구현 전. 2026-09-27 사용자 결정 반영.
관련: FRT-344, BAC-38. 잔액·내역·생성 게이트는 FRT-98/101/99 후속 범위.

## 제품 정책과 구현 범위

랜딩은 월 구독 없이 필요한 만큼 이용하는 크레딧제를 소개한다.
경험 기록·보관·개별 분석은 무료이며 종합·키워드 분석, 이력서·자기소개서 생성은
크레딧 사용처로 설명한다. 패키지 이름·충전량·가격은 공개하되 기능별 차감량과 예상
생성 횟수는 표시하지 않는다. 가입 시 지급량을 약속하지 않는다.

패키지는 백엔드 응답을 우선 사용한다. 서버가 아직 없거나 응답을 사용할 수 없으면
기획안의 패키지를 그대로 표시한다. 구매 가능 여부 필드는 계약에 넣지 않는다.
이번 변경은 패키지 소개와 조회만 구현하며 실제 구매·결제·차감은 구현하지 않는다.
가입 CTA는 /signup으로 연결한다. 결제 버튼이나 Fake door는 추가하지 않는다.

## 공개 GET /credits/packages

인증 없이 읽는 비개인 정보이며 쿠키를 전송하지 않는다. 응답 envelope는 아래와 같다.

```json
{
  "packages": [
    { "id": "lite", "name": "Lite", "credits": 20, "price_krw": 4900 },
    { "id": "basic", "name": "Basic", "credits": 50, "price_krw": 9900 },
    { "id": "pro", "name": "Pro", "credits": 120, "price_krw": 19900 }
  ]
}
```

- 배열 순서가 표시 순서다. `id`는 유일하고 안정적인 패키지 식별자다.
- `credits`와 `price_krw`는 양의 안전한 정수다. 통화는 KRW이며 가격 단위는 원이다.
- 이름과 ID는 앞뒤 공백을 제거하며, 비어 있거나 100자를 넘는 문자열·중복 이름/ID는 허용하지 않는다. 최대 20개 패키지를 허용한다.
- `available`, `purchasable`, `purchase_status`, `top_up_status` 등 구매 가능 여부는 넣지 않는다.
- 기능별 비용표·예상 생성 횟수·가입 지급량·개인 잔액은 이 API에 포함하지 않는다.
- 클라이언트는 명시된 네 필드만 채택하고 알 수 없는 필드는 무시한다.
- 401/403을 받더라도 공개 랜딩에서 세션 갱신이나 로그인 이동을 하지 않는다.
- 현재 프론트는 `cache: no-store`로 마운트당 조회한다. CDN 캐시도 사용하지 않는 계약을
  제안한다. 운영 시 캐시 도입은 별도 합의로 TTL·가격 변경 시 무효화 기준을 정한다.

## 기획안 기본값과 실패 처리

출처: [크레딧 과금 기획안](https://app.notion.com/p/3c373d1b738280d4aa4dcacb5e894ad4).
사용자가 이 기획안으로 공개 패키지를 맞추기로 선택했다.

| 패키지 | 크레딧 | 가격 |
| --- | ---: | ---: |
| Lite | 20 | 4,900원 |
| Basic | 50 | 9,900원 |
| Pro | 120 | 19,900원 |

첫 렌더부터 기본값을 표시한다. 정상 응답을 받으면 목록 전체를 서버 값으로 교체한다.
3초 내 응답이 없거나 네트워크 오류, 비정상 HTTP, JSON 파싱 오류, 빈 배열, 누락·잘못된
필드, 중복 ID를 받으면 기본값을 유지한다. 일부 유효한 항목만 기본값과 섞지 않는다.
언마운트 시 요청을 취소하고 늦은 응답으로 화면 상태를 갱신하지 않는다.

실패 시 오류 배너나 '가격 없음' 화면을 표시하지 않는다. 이는 서버 연결 전에도 기획안으로
소개를 제공하려는 의도적인 fallback이다. 기본값을 숨은 가격 계산이나 결제 승인에 쓰지 않는다.
정책상 '서버가 빈 목록으로 상품을 숨김'은 이번 계약에 없다. 빈 목록도 fallback이다.

서버 값과 기본값이 달라진 후 서버가 실패하면 기본값이 표시될 수 있다. 실제 결제를 붙일 때는
서버의 최신 상품·가격으로 견적을 다시 받아 사용자가 확인하는 별도 흐름이 필요하다.
이번 PR은 결제 견적이나 가격 고정을 보장하지 않는다.

## 비공개 비용과 후속 API 경계

기능별 소모량은 서버 내부 정책으로 유지하며 랜딩이나 생성 직전 비용표로 공개하지 않는다.
패키지 충전량과 가격은 공개 데이터다. 기능별 비용과 혼동해 숨기지 않는다.

잔액·거래내역 숫자를 모두 숨기는 안은 앞선 초안에서 범위를 넓힌 제안이었으며 이번 계약에서
확정하지 않는다. FRT-98/101에서 별도 결정한다. 서버는 정확한 지급·예약·확정·해제 원장을
유지해야 하며 사용자 화면의 표시 정책 때문에 내부 추적 데이터를 버리지 않는다.
실행 시 서버 재검증·멱등 처리·실패 복구는 BAC-36/37/71 범위다.
