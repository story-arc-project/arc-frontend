# FRT-105 frontend behavioral funnel

Approved scope: the user approved implementation after the event mapping and latest-code audit. Extend existing UI and analytics, without new product screens or backend contracts. No additional approval gate is needed.

## Contract
- Preserve existing Notion event names where applicable. Browser actions only; do not emit mission submission/approval/eligibility/grant success or revenue.
- Price rendered, selection, purchase click and notice rendered are separate facts. Retries retain intent identity and never inflate purchase clicks.
- Production /credits/charge currently uses LegacyCharge; instrument it too. Preserve its fallback behavior but explicitly distinguish fallback/unknown catalog from verified API exposure; do not count fallback as valid price exposure.
- Isolate preview/demo/development from production metrics. Funnel capture wrapper must never throw into user actions. All emitted events have event_id, schema_version, occurred_at, environment. IDs are observational, not backend idempotency guarantees.
- No email, URL, entered text, reason text, raw account identifiers. Fixed entry-path enums only. No invented first-exposure/history facts.
- Existing unavailable production mission adapter remains unchanged. Request retries must be marked separately from first clicks.

## Tasks and ownership
1. Root: common typed funnel capture contract, fail-open/environment guard tests, contract document.
2. Credit implementer: CreditCharge/FakeDoorDialog and related tests only. Instrument catalog/selection/purchase/notice/dismiss/mission click with stable flow/intent IDs; integrate common module.
3. Mission implementer: mission UI and related tests plus optional mission-local helpers. View/start/submit click/claim click/referral copy only. No store success events; retry intent differentiated.
4. Root + review agent: integration audit, targeted browser smoke, four validation gates, independent spec/quality review, draft PR to dev. No merge.

## Checks
Meaningful tests: failed catalog excludes valid exposure; StrictMode duplicate exposure; selected snapshot; retry vs new intent; capture throw does not block UI; mock/development guard; unavailable missions do not emit success; entered URL/text excluded. Run lint, typecheck, full unit, build; existing relevant Playwright smoke. No visual design changed.

## Preflight
Tasks 1/2/3 share only the common capture interface: root owns lib/analytics and implementers import lib/analytics/funnel. Credit and mission own disjoint UI directories. All tasks agree on browser-only events and preserve backend gaps. Test assertions must check semantics, not only event count.
