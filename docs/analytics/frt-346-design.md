# FRT-346 구현 설계 초안

2026-10-24 승인한 브라우저 우선 구현 설계. 기준: FRT-346, FRT-345 최신 v0.3 명세 및 dev `0eda1f3` (작업 시작 시 origin/dev fetch로 확인). 구현과 검증 증거는 `frt-346-event-matrix.md`를 참조한다. 운영 배포·실수신은 별도 검증이다.

## 목표

가입→온보딩→기록 작성과 결과 조회→북마크를 연결할 수 있도록 누락된 브라우저 계측을 보완한다. 기존 FRT-330/331, FRT-106, FRT-325 구현을 재사용한다. 브라우저 저장 관측과 서버 최초 완료 사실을 구분한다.

## 확인한 현재 동작

- 새 기록 저장은 record_created를 보내지만 record_id와 작성 시도 ID가 없다. 초안도 전체 목록 count===1이면 first_record_created 후보가 된다.
- 편집 경로에는 archive_entry_resumed가 있다. 기존 기록의 최초 완료 여부는 목록 개수나 클라이언트 마커로 확정할 수 없다.
- markOnceForUser는 localStorage의 읽기→쓰기를 사용한다. 여러 탭의 동시 실행에 대한 원자성을 보장하지 않는다.
- analysis_viewed는 결과가 준비된 뒤 화면을 떠날 때 체류시간과 함께 발화한다. 조회 후 반응의 선후관계용 진입 신호가 필요하다.
- school, department, interest는 기존 가입 폼과 백엔드 프로필 저장 경로에 있다. 학년 전용 필드는 현재 로컬 모델에 없다.

## 접근 비교

1. 브라우저 보완을 먼저 구현하고 서버 의존을 명시한다(추천). 현재 API로 확인할 수 있는 저장·조회·북마크 성공만 발행한다. 최초 완료와 다중 기기 중복 제거의 권위는 서버에 둔다. FE 변경을 독립적으로 검토할 수 있다.
2. BAC-75/73 등 서버 계약과 함께 구현한다. 최초 완료 시각·결과 버전까지 확정할 수 있지만 API·DB·이벤트 발행 계약과 백엔드 작업까지 범위가 확대된다.

## 추천 구현 범위

- 기존 이벤트 대응표를 작성해 정의/타입/실제 발행 위치/실수신/남은 서버 의존을 각각 표시한다.
- 기록 시작·재개·저장·이탈에 같은 entry_attempt_id를 연결하고 저장 성공 후 record_id를 추가한다. 신규·초안 저장·초안→완료·완료 수정·복제를 구분한다. 입력 중 상태 대신 요청 payload 시점의 snapshot을 사용한다.
- 첫 기록 관련 브라우저 신호는 완료 상태에만 적용한다. 목록 count로 사용자 최초 완료를 확정하지 않는다. 서버 최초 완료 계약 전에는 authoritative activation을 미검증으로 둔다. 기존 legacy 이벤트의 의미 변경과 새 계약은 대응표에 명시한다.
- 결과 본문 ready + foreground에서 analysis_result_viewed를 화면 관측당 한 번 발행한다. analysis_id/type, view_id와 관측시각을 연결한다. 기존 analysis_viewed의 체류 관측은 유지한다. 로딩·오류·배경 탭은 조회로 세지 않는다.
- 북마크는 성공 응답 뒤에만 관측한다. 결과별 피드백은 FRT-106의 실제 계약/구현 여부를 먼저 확인하고 연결 ID만 재사용한다. 캠페인 설문을 결과별 긍정 반응으로 대체하지 않는다.
- 가입·온보딩 step/완료·유입 속성은 기존 발행과 SDK 자동 UTM 보존을 확인한 뒤 실제 누락만 보완한다. URL 전체·자유 입력·이메일은 추가 전송하지 않는다.
- 정성 입력은 관리된 field_key/filled 또는 기존 집계 숫자로만 전달한다. 학교·전공·관심분야는 현재 저장 계약을 재사용하고 학년은 미수집으로 명시한다. 새 폼/스키마는 이 FE 묶음에 넣지 않는다.
- 익명→식별, 로그아웃 직전 flush, 계정 변경 후 늦은 응답, StrictMode, 동시 탭을 검증한다. 브라우저 중복 억제와 서버 전역 중복 보장을 구분한다.

## 검증과 완료 경계

dev에서 별도 기능 브랜치/워크트리를 사용한다. 기존 변경을 보존한다. 로직 경계는 TDD로 검증하고 lint/typecheck/test:unit/build 및 관련 Playwright 스모크를 실행한다. PR base는 dev이며 머지는 별도 사용자 지시 후 수행한다.

합성 검증: 신규 초안이 활성화되지 않음, 초안→완료와 완료 수정 분리, 저장 실패/중복 클릭, 요청 snapshot, 결과 ready·가시성·ID 변경, 북마크 성공/실패, 동시 탭/계정 변경/로그아웃 귀속.

실수신 검증: 배포 SHA/환경과 수집 프로젝트를 확인하고 P0 이벤트의 최소 payload 표본과 내부/데모 제외를 점검한다. 테스트 증거와 실수신 증거를 별도로 기록한다. 서버 최초 완료 사실·피드백 계약·배포/로그인 검증이 남으면 FRT-346 전체를 Done으로 처리하지 않는다.
