# FRT-99 잔액 부족 안내 및 충전 페이지

사용자가 생성 요청을 보냈으나 서버가 크레딧 부족으로 거절하면, 기존 오류 화면 대신
부족 모달에서 닫기 또는 `/credits/charge`로 이동할 수 있다. 기능별 실행 비용,
필요 크레딧, 부족량 및 서버 오류 메시지에 포함된 수치는 표시하지 않는다.

## 승인된 흐름 (2026-10-04)

- 종합·키워드 분석 생성/재시도, 이력서 생성/다시 만들기, 자기소개서 생성에 적용한다.
- 명시적인 부족 응답만 처리한다. 잔액 조회 실패·네트워크 오류를 부족으로 추측하지 않는다.
- 모달을 닫으면 현재 폼 입력·선택을 유지한다. 충전 페이지로 이동하면 현재 라우트를 떠난다.
- 자동 재실행, 클라이언트 차감·지급 및 실결제는 없다. 개별 분석·결과 열람·다운로드에는 적용하지 않는다.
- 충전 페이지에는 공개 패키지·가격을 보여준다. 진입 직후 준비 중 안내는 표시하지 않는다.
- 사용자가 패키지를 선택하고 **결제하기**를 누른 시점에만 준비 중 안내를 표시한다.
- 결제수단 선택·구매 의사 저장/계측·리워드 연결은 후속 Fake Door 범위다.

## UI 상태

| 화면 | 상태 | 동작 |
| --- | --- | --- |
| 생성 화면 | 요청 중 | 중복 실행 방지, 기존 입력 유지 |
| 생성 화면 | 명시적 크레딧 부족 | 수치 없는 모달, 닫기 / 충전 페이지로 이동 |
| 생성 화면 | 일반 실패 | 기존 오류 처리 |
| 충전 페이지 | 로딩 | 패키지 스켈레톤, 결제 버튼 비활성 |
| 충전 페이지 | 정상 목록 | 공개 패키지 이름·크레딧·가격, 미선택 상태 |
| 충전 페이지 | 조회 실패/비정상/빈 목록 | 기존 공개 패키지 API의 전체 기본 목록 fallback |
| 충전 페이지 | 패키지 선택 | 선택 표시 및 결제 버튼 활성 |
| 충전 페이지 | 결제 버튼 클릭 | 준비 중 모달, 결제·충전되지 않았음을 안내 |

## 구현 및 검증

기존 공개 패키지 조회와 Dialog/Button을 재사용한다. API 전역 인터셉터 대신 해당 생성
화면에서 공통 오류 판별·모달을 호출하여 무료 기능까지 영향을 주지 않도록 한다.

오류 판별 단위 테스트, 입력 보존 및 준비 중 안내 시점 테스트, Storybook 상태/상호작용,
Playwright의 부족→닫기/충전 이동 및 320/390/1440px 화면으로 검증한다.
백엔드 API를 스텁한 프론트 검증은 실제 운영 예약·차감·해제 정합성의 증거가 아니다.
