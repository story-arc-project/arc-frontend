# ARC Slack 메시지 형식

정본(Source of truth): Notion '리서치/온보딩 자료 › Slack 메세지 형식'
https://app.notion.com/p/Slack-37673d1b738280a3aeaeee805496d521

아래는 위 노션 페이지를 미러링한 것이다. **발송 전 노션 원본을 다시 확인해 최신 형식과 어긋나지 않는지 대조할 것**(형식이 갱신될 수 있음). Notion MCP가 가능하면 `notion-arc` 로 위 페이지를 다시 읽어 사용한다.

세 가지 목적별 템플릿이 있다. 요청/공유/토의 중 상황에 맞는 하나를 고른다.

---

## [요청] — 상대에게 확인·진행을 부탁할 때

```
**[요청] {요청 제목}**
@{대상자}
- 요약: {무엇을 요청하는지 한 줄로 설명}
- 기한: {언제까지 필요한지}
- 참고: {관련 자료/링크/맥락}

**[배경]**
{왜 이 요청이 필요한지 설명합니다.}

**[상세 요청]**
아래 내용을 중심으로 확인/진행 부탁드립니다.
1. {요청 사항 1}
2. {요청 사항 2}
3. {요청 사항 3}

**[자료]**
- {문서/파일/링크}

**[비고]**
{주의할 점, 애매한 부분, 추가 설명}
```

## [공유] — 진행 상황·결과를 알릴 때

```
**[공유] {공유 제목}**
@{대상자 또는 채널}
- 요약: {공유 내용의 핵심}
- 기한: {확인 필요 시점 / 없으면 "별도 기한 없음"}
- 상태: {현재 상태}
- 참고: {관련 자료/링크}

**[상세]**
{공유할 내용을 자세히 설명합니다.}

**[영향 범위]**
이 내용은 아래에 영향을 줄 수 있습니다.
- {영향 1}
- {영향 2}

**[다음 액션]**
{필요한 후속 조치가 있다면 적습니다.}
```

## [토의] — 의견·결정을 받아야 할 때

```
**[토의] {토의 제목}**
@{대상자}
- 요약: {무엇에 대해 의견이 필요한지}
- 기한: {언제까지 의견을 받고 싶은지}
- 쟁점: {가장 중요한 논의 포인트}
- 참고: {관련 자료/현재 상황}

**[배경]**
{왜 이 토의가 필요한지 설명합니다.}

**[현재 선택지]**
1. {선택지 A}
   - 장점:
   - 단점:
2. {선택지 B}
   - 장점:
   - 단점:

**[현재 제안]**
저는 {추천 방향}이 적절해 보입니다. 이유는 {추천 이유}입니다.

**[요청]**
의견 있으시면 이 스레드에 남겨주세요. 특히 {특정하게 의견 받고 싶은 부분}에 대한 의견을 부탁드립니다.
```

## 작성 규칙

- **행동의 언어**(CLAUDE.md): "어떻게 구현했나"가 아니라 "무엇이 가능해졌고 상대가 무엇을 하면 되는가"를 먼저.
- 멘션은 실제로 알림이 가도록 `<@U…>` 형식을 쓴다(플레인 `@이름`은 알림이 안 감). 멤버 ID는 `scripts/slack.py lookup --query <이름>` 으로 찾는다.
- 링크는 Slack 마크다운(`<url|텍스트>`가 아니라 표준 마크다운 `[텍스트](url)` 또는 raw URL)로. Notion·Linear 링크를 [자료]/[참고]에 첨부.
- 이모지는 `:tada:` 같은 코드 표기 사용 가능.
